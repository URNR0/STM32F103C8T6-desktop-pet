# STM32F103C8T6 桌面宠物 —— 参考代码接入指南

这份指南配合本目录下的参考代码使用。参考代码分两层:

| 文件 | 作用 | 必选? |
| --- | --- | --- |
| `oled.h` / `oled.c` | SSD1306 屏幕驱动(软件 I2C) | 屏幕还没自己驱动起来时用 |
| `font8x8.h` | 8x8 英文/数字小字库(配合 OLED 显示文字) | 屏幕用我们的驱动时必选 |
| `pet.h` / `pet.c` | 宠物动画: 表情 + 待机动画脚本 | 必选 |
| `pet_frames.h` | 自动生成的宠物三帧图片(睁眼/闭眼/开心) | 必选 |
| `uart_cmd.h` / `uart_cmd.c` | 串口收指令: 环形缓冲 + 行解析 + 命令表 | 必选 |
| `main_example.c` | 怎么把上面这些拼进你的 main.c | 参考 |
| `gen_assets.py` | 重新生成宠物形象/帧的 Python 脚本 | 可选 |

> 如果你的屏幕**已经点亮**(自己写过驱动), 那就别用我们的 oled.c, 保留你的驱动,
> 只要保证下面这些函数存在即可: `OLED_ShowFrame(帧)`, `OLED_Refresh()`,
> `OLED_ShowString(x,y,字符串)`, `OLED_ShowNum(x,y,数字,位数)`。
> 没有的函数可以空着或改个名字, 让 pet.c 能编译就行。

## 第 1 步: 怎么"搭一个 Keil 库", 然后做动画

### 1.1 "搭库"是什么意思?

初学者常被"库"两个字吓到。其实在 Keil 里**库 = 你自己写的一堆 `.c` / `.h` 文件,
按功能分好组**。比如:

- OLED 驱动(`oled.c/.h`) —— 管屏幕怎么亮、怎么画图
- 宠物模块(`pet.c/.h`) —— 管宠物长什么样、怎么动
- 串口指令(`uart_cmd.c/.h`) —— 管听手机/电脑的话

每个模块只干一件事, 互相通过"头文件里的函数名"合作, 这就是模块化。
好处: 以后加 DHT11 传感器, 就多一个 `dht11.c/.h` 模块, 别的代码不用动。

### 1.2 把文件加进 Keil 工程(3 分钟)

1. 把本目录下的 `.c` / `.h` 文件**复制**到你的工程文件夹里
   (比如放在 `Core/Src` 旁边新建一个 `MyLib` 文件夹)。

2. 打开 Keil 工程 → 左侧 Project 树 → 点工具栏**“Manage Project Items”**
   (一个打开的抽屉图标), 新建分组: `MyLib`。

3. 选中 `MyLib` 分组 → **Add Existing Files** → 把下面的 `.c` 文件加进去
   (`.h` 不用加, 它们会被 `#include` 自动找到):
   ```
   oled.c      (屏幕还没亮就用)
   pet.c
   uart_cmd.c
   ```

4. 告诉编译器去哪里找 `.h` 文件:
   魔法棒(Options for Target) → **C/C++** 选项卡 → **Include Paths** →
   添加你放头文件的文件夹路径。

5. 编译。如果报“找不到某函数”, 多半是某个 `.c` 没加进工程或路径没配好。

### 1.3 动画到底怎么做的?(原理一句话 + 代码怎么看)

动画 = 每秒切换多张图片, 就像表情包 GIF。三步:

1. **画帧**: 把宠物每一瞬间的样子画成一张 128x64 的小图。
   我们给你画好了三帧(`pet_frames.h`): 睁眼、闭眼、开心。
2. **存帧**: 每帧 = 1024 个字节的数组(`128 列 × 8 页`, 每字节是纵向 8 个点)。
3. **定时换帧**: `Pet_Update()` 记录"上次换帧的时间", 
   时间一到(`HAL_GetTick()` 毫秒计时)就换下一帧, 见 `pet.c` 里的 `anim_idle[]` 表:

   ```
   睁眼(2 秒) → 眨眼(0.12 秒) → 睁眼(1.2 秒) → 开心(0.8 秒) → 循环
   ```

想换形象: 两个办法。
- 简单: 用 **PCtoLCD2002**(免费)画 128x64 图, 选"列行式、阴码、纵向取模、
  每个字节最高位在上"再导出, 把数组换成你的;
- 会一点 Python 的话, 直接改 `gen_assets.py` 重跑, 会自动生成新的 `pet_frames.h`。

## 第 2 步: 串口收指令的框架(本目录 uart_cmd.*)

### 2.1 你订的协议(够简单, 够好调)

手机/电脑发来的是**一行文字**, 以回车结尾, 大小写不敏感:

| 指令 | 效果 |
| --- | --- |
| `NORMAL` | 回到正常表情 |
| `BLINK` | 眨眼 |
| `HAPPY` | 开心 |
| `PING` | 回一句 `PONG`(测试链路通不通) |
| `HELP` | 列出现有指令 |

加新命令 = 在 `uart_cmd.c` 的命令表里加一行, 不用改别的。

### 2.2 数据是怎么流进来的(从硬件到动画)

```
手机蓝牙 / USB串口  ──>  USART1 引脚 ──> 中断一个字节一个字节收
                                       │  每收 1 字节 → UartCmd_OnByte(字节)
                                       v
                                 环形缓冲区(排队)
                                       │  主循环里 UartCmd_Poll() 取出来
                                       v
                                  攒够一行(看到回车) → 查命令表 → Pet_SetFace(表情)
```

### 2.3 你要在自己工程里补的 3 处(详见 main_example.c)

1. **CubeMX 里**配置 USART1(异步、115200、8N1), **并勾选 USART1 全局中断**;
2. **main() 里**: `HAL_UART_Receive_IT(&huart1, &rx_byte, 1);` 启动中断接收;
3. **回调里**: 每个字节转交 `UartCmd_OnByte(rx_byte)` 后,
   **必须再调一次 `HAL_UART_Receive_IT(...)` 重新挂起**, 否则只收第一个字节。

> 手机测试: 下载一个"蓝牙串口调试助手"(安卓 iOS 都有),
> 蓝牙连上模块后文本框输入 `HAPPY` 点发送即可。
> 电脑测试: 用串口助手(波特率 115200)发 `HAPPY` + 回车。

## 第 3 步: 接线对照

```
OLED            STM32F103C8T6
SCL ──────────> PB6
SDA ──────────> PB7
VCC ──────────> 3.3V
GND ──────────> GND(共地)

USB转TTL(CH340 等, 建议选 3.3V 电平的)     STM32
TX  ──────────────────────────────> PA10 (USART1_RX, 交叉接!)
RX  <──────────────────────────────  PA9  (USART1_TX)
GND ──────────────────────────────> GND

ST-Link: 只用 SWCLK、SWDIO、GND 三根, 目标板自己用 USB 供电(你的接法正确, 别改)
```

两个注意:
- **TX/RX 要交叉**: 模块的 TX 接单片机的 RX(PA10), 模块的 RX 接单片机的 TX(PA9)。
- 很多 CH340 小板在 5V 档, 接 3.3V 单片机建议选**3.3V 供电档**, 或 TX 串一个 1k 电阻。

## 第 4 步: 坑和排查方法(重点)

### A. OLED 黑屏 —— 按顺序查, 90% 是下面 4 个之一

| # | 检查项 | 怎么查/怎么修 |
| --- | --- | --- |
| 1 | **上电了吗 / 供电够吗** | VCC 接 3.3V, 屏幕模块或主板的电源灯亮不亮; 换一根杜邦线试试 |
| 2 | **I2C 地址** | 默认 `0x3C`。改 `oled.h` 里 `OLED_I2C_ADDR` 为 `0x3D` 试一次 |
| 3 | **电荷泵没开** | `oled.c` 初始化序列里的 `0x8D, 0x14` 不能少, 少了 100% 黑屏 |
| 4 | **SDA/SCL 上拉** | 模块一般自带 4.7k 上拉; 若没有, SDA、SCL 各接 4.7k 到 3.3V。没上拉时开漏输出拉不高, 必黑 |

其它: 画面上下颠倒 → 初始化里 `0xC8` 改 `0xC0`;
左右镜像 → `0xA1` 改 `0xA0`。先确认是 128x64 的屏(还有 128x32 的, 驱动不同)。

**黑屏自查小技巧**: 编译烧录后, 如果 `OLED_Fill()` 能把整屏点亮, 说明硬件和 I2C 没问题,
问题在初始化序列或你的画图逻辑。

### B. 串口收不到 / 乱码

- **只收到一次**: 回调里忘了重新 `HAL_UART_Receive_IT`, 补上即可(见 main_example.c)。
- **完全收不到**: 确认 CubeMX 里勾选了 **USART1 全局中断**;
  TX/RX 有没有接反; 模块要共地。
- **乱码**: 波特率不一致(两端都要 115200); 发送时结尾加了回车没有(必须 `\r` 或 `\n`);
  用串口调试助手对比, 先用电脑串口调通, 再上蓝牙, 别一起上。
- **回显叠加/命令不执行**: 有些上位机默认"发送新行"带 `\r\n`, 我们是支持的;
  如果发的是二进制或带空格、大小写混着, 框架做了裁剪, 应该没问题, 先发 `PING` 试。
- **蓝牙模块(以后买)默认波特率 9600**: 用 `AT+BAUD8` 之类改成 115200 或把程序波特率改成 9600。

### C. Keil 编译 / 下载

- 报 `undefined symbol` / `not found` → 有 `.c` 文件没加入工程, 或文件没编进去
  (看左侧文件名前面有没有灰色的减号图标)。
- 报头文件找不到 → Include Paths 没配好(见 1.2 第 4 步)。
- 下载时 `No target connected` → 检查 ST-Link 三根线(SCK/SWDIO/GND)、
  **BOOT0 跳线帽拨到 0**、Keil 的 Debug 设置里选 ST-Link 并确认 SW 模式。
- 中文注释乱码不影响编译; 想好看就保证文件是 UTF-8 带 BOM(本目录文件已带)。
- 如果个别文件报注释相关的语法错, 魔法棒 → C/C++ → 勾选 **C99 Mode**。

### D. 动画相关

- 画面闪 → 用了逐字/逐点直写屏幕, 请改成"先画进缓冲区, 最后 `OLED_Refresh()` 一次"。
- 动画太慢 → 软件 I2C 刷新整屏大约几十毫秒, 待机动画足够;
  以后要更顺滑, 改用硬件 I2C(400kHz)或只更新局部区域。
- 切换表情没反应 → 先查指令链路: 串口助手发 `PING` 看回不回 `PONG`;
  回 `ERR:UNKNOWN` → 命令拼写/回车问题; 完全没反应 → 中断回调那段没接好。

## 第 5 步: 下一步(等你买到模块)

- **JDY-31 蓝牙(约 10-15 元)**: 透传模式 = 透明串口, 程序不用改,
  手机连上后按第 2 步的协议发命令即可。接线 TX→PA10、RX→PA9(交叉)、VCC 3.3V、GND 共地、
  波特率默认 9600(程序统一改 9600 最省事)。
- **DHT11 温湿度(约 2-5 元)**: 一根 GPIO 单总线, 加一个 `dht11.c` 模块;
  把温度读出来放到宠物动画下面显示(`OLED_ShowNum` 已备好), 太热就切"开心/难受"表情 ——
  这就是"宠物感知环境"的第一步。
- **Python 上位机**: `pyserial` 打开串口 → `ser.write(b"HAPPY\r\n")` 就能遥控,
  之后可以加按键/滑条/简易 UI。

## 最后

调试口诀:**一次只改一个地方**。先点亮屏幕, 再让宠物动, 再用串口助手发指令,
每一步通了再进下一步。祝贺你, 这是嵌入式里最经典的"点亮屏幕 + 串口交互"组合,
跑通了你就有信心继续玩下去了。
